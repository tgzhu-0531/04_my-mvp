## 修复轮次时间线

### 第 1 轮：初始搭建
- **耗时**: ~15 分钟
- **操作**: 读取 PRD → 搜索 5 省电价数据 → 设计数据库/CSV 结构 → 创建前端 → 创建文档
- **产出**: 18 个文件的初始版本
- **结果**: ✅ 初始版本创建完成

### 第 2 轮：总览页卡片接入 + 返回总览 (PRD §11)
- **耗时**: ~10 分钟
- **操作**: 更新根 `index.html` → 添加 ChatGPT 卡片 → 添加返回总览链接
- **问题**: 使用 `Out-File` 完整重写了根 index.html，覆盖了其他 Agent 的卡片和"国外商业"面板
- **修复**: 改为精准替换 + 将卡片放入"国外商业"面板 (用户指出)

### 第 3 轮：BOM 污染修复
- **耗时**: ~20 分钟
- **现象**: 用户 IIS 部署后页面空白，"数据未加载"
- **根因**: PowerShell `Out-File -Encoding utf8` 给所有 CSV/JSON 文件添加了 BOM (EF BB BF)
  → CSV 首字段变成 `\uFEFFprovince_id`
  → `obj.province_id` 全部返回 `undefined`
  → 数据加载静默失败
- **修复过程**:
  1. 首次尝试: 使用 .NET 方法 `[System.IO.File]::WriteAllBytes` 去除 BOM ✅
  2. 但后续的 `Set-Content -Encoding utf8` 又把 BOM 加回去了 ❌
  3. 最终方案: 改用 `[System.IO.File]::WriteAllText($path, $content, [System.Text.UTF8Encoding]::new($false))`
- **额外防御**: 在 `parseCSV()` 和 `loadCSV()` 中加 BOM 检测和移除

### 第 4 轮：Syntax Error (孤儿 catch)
- **耗时**: ~15 分钟
- **现象**: 用户部署后页面依然空白
- **根因**: 我在 app.js 中用 PowerShell 的字符串替换加 `try/catch` 时，
  `try {` 没写进去但 `} catch (e) {` 写进去了
  → JS 语法错误 (orphan catch)
  → 整页 JS 不执行
- **修复**: 用 Node.js 的 `fs.writeFileSync` 完整重写 initApp 函数
- **教训**: PowerShell 的字符串转义 (`\"`, `` `n ``) 在处理 JavaScript 时极为不可靠

### 第 5 轮：Chart.js CDN 阻塞
- **耗时**: ~10 分钟
- **现象**: 数据链路通了但页面依然白屏
- **根因**: Chart.js CDN (cdn.jsdelivr.net) 在国内可能被墙
  → `<script>` 标签是阻塞式的
  → 浏览器等待 CDN timeout (60s+)
  → 排在后面的 `config.js` / `app.js` 永远不加载
- **修复**: 将 Chart.js 移到 `<body>` 底部 + 加 `async` + 所有本地脚本优先加载

### 关键发现：HTML ID 与 JS ID 不匹配
- **耗时**: ~60 分钟 (多轮排查最终定位)
- **现象**: `v2.html` 能正常工作但 `index.html` 不行
- **根因**: 当我用 `v2.html` 的内联 JS 替换 `index.html` 时：
  - 原版 HTML 用 `id="ov-province-count"`、`id="compare-body"`、`id="analysis-text"`
  - v2 的 JS 用 `getElementById("s-pv")`、`getElementById("t-body")`、`getElementById("analysis")`
  - 页面加载后 JS 执行到 `document.getElementById("s-pv")` 返回 `null`
  - 抛出 `Cannot set properties of null` 被 catch 捕获
  - 整页显示"数据加载失败"而不是真实数据
- **教训**: 碎片化替换 HTML 结构不可靠。两套代码的 DOM 合约(ID)必须对齐

### 最终状态
- `index.html` 基于 `v2.html` 的架构重建
- 使用内联 JS (无外部文件依赖)
- 三个视图 (概览/详情/数据源) 通过内联 JS 切换
- 所有元素 ID 与 JS 匹配

- ID 不匹配 ✅ (修复)
- 脚本加载顺序 ✅ (修复)

### 2. 工具链选择教训

| 操作 | 最初选择 | 教训 | 最终方案 |
|------|---------|------|---------|
| 文件编辑 | `apply_patch` | 格式过于严格 | `mcp__node_repl__js` + `fs.writeFileSync` |
| 字符串替换 | PowerShell | 转义地狱，引号处理灾难 | Node.js |
| 长文本写入 | `Set-Content` | 自动加 BOM | `fs.writeFileSync(path, content, "utf-8")` |
| 服务器持久化 | `Start-Process` / `Start-Job` | 权限/环境变量冲突 | `mcp__node_repl__js` 长期存活 |

### 3. 浏览器测试缺失

- 没有可用的浏览器自动化工具 (Playwright/jsdom 未安装)
- 无法直接查看浏览器控制台错误
- 所有测试依赖 Node.js fetch 模拟，无法捕捉 DOM 运行时错误
- 如果能实际查看控制台，ID 不匹配问题可以 3 分钟内发现
