### 详细步骤清单

#### 第 1 步：读 PRD（3 分钟）

- 🧠 **大模型推理**：理解 16 章需求全文，提取核心约束（5 省、SQLite/CSV 双模、config.json 切换、不得编造数据、数据状态标注、接入总览页等）
- 🤖 **Agent 执行**：调用 `Skill:pdf-reading` 按指导执行 `pdfinfo` → `pdffonts` → `pdftotext -layout` 三步诊断并提取全文

#### 第 2 步：方案规划（2 分钟）

- 🧠 **大模型推理**：确定技术栈（纯前端 SPA + Chart.js + Python 轻量后端）、数据表结构（5 表）、文件目录布局、搜索策略（优先省级发改委官网）
- 🤖 **Agent 执行**：创建 6 个 Task 跟踪项

#### 第 3 步：数据搜索（12 分钟）

- 🧠 **大模型推理**：判断来源可靠性 -> 优先采用能直接打开的官方政策原文（江苏发改委、浙江政务网），对 WAF 防护站点通过转载/行业媒体获取；在政策文件只有浮动比例无绝对价格时，制定"modeled"推算策略
- 🤖 **Agent 执行**：8 次 WebSearch（5 省 + 3 次补充）、5 次 WebFetch（获取江苏/浙江/北极星/山东/行业全景页面原文）

#### 第 4 步：数据建模（5 分钟）

- 🧠 **大模型推理**：设计 5 表结构（regions / policies / time_periods / price_points / sources），预留 missing_data 表；设计 4 阶 data_status 标注体系（confirmed / modeled / estimated / missing）；决定保留 original_name 和 standard_category 双字段以支持各端口径差异
- 🤖 **Agent 执行**：创建 CSV 数据目录，Write 写入 5 个 CSV 文件

#### 第 5 步：后端开发（3 分钟）

- 🧠 **大模型推理**：设计 RESTful API 接口（/api/regions, /api/policies, /api/price-points/by-region 等），决定用 Python 标准库 http.server 零依赖
- 🤖 **Agent 执行**：Write init_db.py（SQLite 建表 + CSV 导入 + 缺失数据插入）、Write server/app.py（全 API 端点）

#### 第 6 步：前端开发（10 分钟）

- 🧠 **大模型推理**：调用 `Skill:frontend-design` 确定配色语言（深蓝 #0b3d5f + 琥珀 #f49d37 + 暖灰背景）、布局策略（6 功能区 SPA）、规避三个常见 AI 模板陷阱；首页不出现在线配置等内部信息；设计对比表 + Chart.js 叠图曲线作为核心视觉元素
- 🤖 **Agent 执行**：Write index.html（完整单页应用，含全部 HTML/CSS/JS + Chart.js CDN 引用）

#### 第 7 步：文档编写（5 分钟）

- 🧠 **大模型推理**：区分四份文档的定位（README = 项目操作手册、DATA_DICTIONARY = 字段级参考、DATA_SOURCES = 审计追溯、KNOWN_LIMITATIONS = 诚信披露）
- 🤖 **Agent 执行**：Write 4 份 md 文档

#### 第 8 步：接入总览页（3 分钟）

- 🧠 **大模型推理**：阅读根目录 index.html 了解现有结构（其他 Agent 卡片、tab 分类），确定 Claude 卡片应放在"国外商业"tab，更新状态为"已部署"
- 🤖 **Agent 执行**：Read 根目录 index.html → Edit 两次（先激活 Claude Desktop 卡片，修复重复卡片问题）

#### 第 9 步：验证（2 分钟）

- 🧠 **大模型推理**：配置文件是否完整、CSV 行列数是否合理、总览页入口是否正确
- 🤖 **Agent 执行**：Bash find + du + wc 统计文件规模和行数，Grep 验证卡片位置

#### 第 10 步：输出复盘（5 分钟）

- 🧠 **大模型推理**：按复盘总结模板组织内容，回顾整个过程的关键决策和问题
- 🤖 **Agent 执行**：Write RETROSPECTIVE.md

## 五、经验教训与总结

### 🟢 做得好的

1. **数据诚信**：严格遵守"不得编造数据"禁令，所有价格值明确标注了 confirmed / modeled / estimated / missing 四种数据状态，用户可以追溯到每个数字是来自官方文件、基于浮动比例推算，还是估算值
2. **架构决策正确**：纯前端 SPA + Chart.js + CSV 为核心存储的方案，使得 CSV 模式零依赖即可运行，完全兼容 GitHub Pages 和 IIS 静态托管
3. **配置驱动数据源切换**：config.json 一个字段切换 csv/sqlite 模式，前端 initApp() 统一加载，没有维护两套代码
4. **UI 风格有辨识度**：深蓝+琥珀+暖灰配色区别于常见的 AI 模板色调，首页面向业务用户而非开发者，规避了技术细节展示

### 🔴 做得不够的

1. **总览页首次修改产生重复卡片**：分别在"国内商业"和"国外商业"两个 tab 都插入了 Claude 入口，不得不 grep + edit 二次修正。**教训**：修改大型已有文件时应先 grep 现有结构再动手
2. **部分价格为推算值而非官方绝对值**：虽然标注了 modeled/estimated，但对于需要精确计费的用户可能不够准确。**教训**：应在 README 中更醒目地标注此限制
3. **行政区域表区县级未填充**：表结构预留了 `parent_id` 和 `level=district`，但没有实际数据，PRD 要求虽有提及但优先级被我放在了 MVP 范围外

### 📈 后续改进建议

1. **数据补充**：对接各省电网公司每月代理购电价格公告的实时/近实时接口，提升价格准确性
2. **功能增强**：增加电价计算器（输入负荷曲线估算电费）和历史趋势对比功能
3. **自动化**：建立定时检测各省发改委/电网官网政策更新的自动化管道，有新政策时主动通知维护人员
4. **区县数据填充**：补充深圳、苏州、宁波等独立执行电价政策的城市数据
5. **扩展至全国**：5 省验证链路完成后，扩展到全部 31 个省/市/自治区
