## 五、经验教训与总结

### 🟢 做得好的
1. **架构分离** — Flask API 和静态 SPA 解耦，一句话 config.json 切换数据源，两种场景都能正常运行
2. **数据可追溯** — 每条数据标注来源 URL+机构+时间，缺失数据记录检索过程和判断依据，严格遵守"不编造"原则
3. **可折叠分区系统** — 不仅满足PRD功能要求，还额外实现了 localStorage 折叠状态持久化，提升了产品体验
4. **人机交互迭代充分** — 7 轮修正从"能用"打磨到"界面均衡"，首页经历了 4 次大改达到业务用户视角
5. **技能包可复用** — 将完整工作流打包为 Skill，下次类似任务可复用

### 🔴 做得不够的
1. **CSV 表头 Bug** — `PRAGMA table_info` 的 `row[0]` 取了 cid 数字，写了 data_import.py 却没立刻验证输出，直到 IIS 部署后才发现首页省份数为 0
2. **IIFE 闭合遗漏** — 编辑 charts.js 添加新函数后漏了 `})();`，PriceCharts 未定义错误卡了用户一次
3. **缺少浏览器实测** — 生成代码后没有花 30 秒在浏览器里打开页面验证一次加载效果。ChatGPT 的 BOM Bug 暴露了同样的问题
4. **PRD 版本跟踪不系统** — 跨版本迭代时没有工具化地对比 PRD 各节差异，第11节的重写要求是用户指出后才做的
5. **测试覆盖为零** — 全手动测试，无单元测试无集成测试，典型 MVP 风格

### 📈 后续改进建议
1. 建立月度数据更新机制，跟踪各省发改委政策变化
2. 扩展至全国 31 省，接入电网 API 获取实时代理购电价格
3. 增加用电成本计算器（基于分时电价模拟企业电费）
4. 增加 Docker 部署配置，减少环境依赖
5. 浙江省 2026 年新政策实施后及时更新数据
6. 给 data-loader.js 补单元测试，避免 CSV 模式下的字段解析问题
