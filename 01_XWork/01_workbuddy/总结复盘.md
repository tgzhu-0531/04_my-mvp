# 城市分时电价观察站 MVP · 项目总结复盘

> **版本**: 1.0.0  
> **构建日期**: 2026-07-25  
> **模型**: Deepseek-v4-flash  
> **PRD 版本**: v0.1（5次迭代更新）

---

## 一、项目概述

搭建"中国城市分时电价观察站"MVP，基于政府公开政策文件展示广东、江苏、山东、浙江、内蒙古 5 个重点省份的工商业分时电价政策、时段结构、价格曲线和数据来源追溯。

最终交付 **22 个文件**（+ 门户页 + 技能包），覆盖网站代码、SQLite 数据库、CSV 数据、数据字典、数据源清单、README、已知限制说明、总结复盘和技能包。

---

## 二、需求理解与演变

PRD 在整个构建过程中经历了多次实质更新（跨版本累积），最终版相比初版新增/修订了以下关键内容：

### 第 7 节 — 数据访问要求（新增）
- 明确两个场景：本地验证（sqlite）vs 静态展示（csv）
- 要求前端读取 JSON 配置文件动态切换数据源
- 配置文件字段示例为 `dataSource: "sqlite"`（camelCase）

### 第 10 节 — 部署与编码要求（新增）
- Windows IIS 和 GitHub Pages 双环境兼容
- `index.html` 为默认首页
- 全站 UTF-8 编码
- JSON 配置文件切换数据源

### 第 11 节 — 网页呈现要求（大幅重写）
- 面向业务用户，不展示开发者技术信息
- 需要 Top5 省份对比表（含尖/峰/平/谷/深谷分类）
- 需要基于数据的一句话分析结论
- 多省对比曲线图，不展示单一省份样例
- 不适用时段标注"不适用"或"未公开"
- 首页可折叠分区，状态存 localStorage
- 摘要数字可点击穿透

### 第 13 节 — 交付物要求（迭代明确）
- SQLite + CSV 双模式数据源交付
- 数据库初始化脚本 + 数据导入脚本
- 可运行网站 + 完整文档

## 三、架构设计决策

### 3.1 架构演进

| 版本 | 架构 | 原因 |
|------|------|------|
| v1（初版） | Flask SSR | 快速 MVP 原型 |
| v2（重构） | 静态 SPA + 可选后端 API | PRD §10 要求 IIS/GitHub Pages 静态兼容 |
| v3–v5（迭代） | 同上，持续修复优化 | 按最终版 PRD §7/§11 要求调整 |

### 3.2 最终技术栈

```
前端: 纯静态 SPA → HTML + CSS + Chart.js CDN
数据层: data-loader.js → 统一接口，csv / sqlite 双模式
路由: Hash-based（兼容 IIS 默认文档，无需 URL 重写）
后端（可选）: Flask API → 仅 sqlite 模式本地验证
编码: 全站 UTF-8
配置: config.json → 用户手工 selected: "csv" | "sqlite"
架构: 门户 + 子项目 → 06_XWork/index.html（对比总览）+ 各 Agent 子目录
```

### 3.3 门户架构设计

```
06_XWork/index.html      ← AI Agent 对比总览门户
01_workbuddy/workbuddy.html  ← WorkBuddy MVP（含返回总览导航）
02_trae/                  ← 预留（TRAE Work）
03_qoder/                 ← 预留（QoderWork）
04_kimi/                  ← 预留（Kimi Work）
05_dumate/                ← 预留（百度搭子 DuMate）
```

门户位于工作空间根目录，各 Agent 版本为同级兄弟目录，便于 GitHub Pages 部署和管理扩展。

### 3.3 数据模型（5 表）

```
regions       行政区域（省/市/区三级，parent_id 自引用）
policies      电价政策（文号、用户类型、电压等级、季节、平段电价）
time_periods  分时时段（原始名称、标准分类、起止时间、电价）
data_sources  数据来源（URL、机构、时间、可信度）
missing_records 缺失数据记录（检索过程、判断依据）
```

设计理由：每个省份可能有多个政策（不同用户类型/季节），每个政策有多个时段。来源独立成表便于追溯。缺失记录单独建表确保"不编造数据"原则可执行。

## 四、关键 Bug 与修复

### Bug 1: CSV 导出表头错误（v4 修复）
- **现象**: 首页显示"已收录省份 0"，政策/时段/来源数正常
- **根因**: `server/data_import.py` 中 `PRAGMA table_info` 返回 `(cid, name, ...)`，`row[0]` 取了 cid 数字而非字段名
- **修复**: `row[0]` → `row[1]`
- **教训**: SQLite PRAGMA 返回值列顺序需确认，不能默认 `row[0]`

### Bug 2: PriceCharts 未定义（v5 修复）
- **现象**: JS 控制台 `PriceCharts is not defined`
- **根因**: `js/charts.js` 的 IIFE `const PriceCharts = (() => { ... })();` 末尾漏了 `})();`
- **修复**: 补上 `})();`
- **教训**: IIFE 模式编辑时需要检查首尾闭合

### Bug 3: async/await 遗漏（v5 修复）
- **现象**: `mode.toUpperCase is not a function`
- **根因**: `renderAbout()` 中 `DataLoader.getMode()` 未 `await`，拿到 Promise 对象
- **修复**: 加 `await`，函数改为 `async`
- **教训**: async 函数调用不是自动 await 的，每个调用点都需要 `await`

### Bug 4: 配置文件字段命名不一致（v3 修复）
- **现象**: PRD 示例用 `dataSource`（camelCase），实际用 `data_source`（snake_case）
- **修复**: 统一为 camelCase，包括 `dataSource`、`csvDataDir`、`apiBaseUrl`
- **教训**: 配置文件的接口约定和 PRD 应保持一致

## 八、经验教训

### 做得好的
1. **架构分离**: Flask API 和静态 SPA 解耦，两种场景都能正常运行
2. **数据可追溯**: 每条数据标注来源，缺失数据记录检索过程，严格遵守"不编造"原则
3. **用户体验迭代**: 从初版到最终版，首页经历了 4 次大改，越来越贴近业务用户视角
4. **配置驱动**: config.json + 前端动态读取，符合 PRD 对配置分离的要求
5. **可折叠分区**: 所有内容分区可折叠带 localStorage 持久化，用户控制视图深度
6. **AI Agent 对比门户**: 多 Agent 同级目录，便于对比展示和扩展

### 做得不够的
1. **CSV 导出 bug 发现晚**: 应该写完 data_import.py 立刻验证 CSV 表头
2. **JS IIFE 闭合遗漏**: 编辑 charts.js 添加新函数时没检查文件末尾闭合
3. **PRD 版本跟踪**: 跨版本迭代时没有系统性地对比差异，漏掉了第 11 节的重写要求
4. **测试覆盖**: 纯手动测试，没有单元测试或集成测试
5. **UI 细节打磨**: 返回栏的样式经历了 3 次调整（Teal 背景 → 透明条 → 导航栏胶囊）才达到用户满意

### 后续建议
1. 建立月度数据更新机制，跟踪各省政策变化
2. 扩展至全国 31 省，接入电网 API 获取实时代理购电价格
3. 增加用电成本计算器（基于分时电价模拟企业电费）
4. 增加 Docker 部署配置
5. 浙江省 2026 年新政策实施后及时更新
6. 其他 4 个 Agent 版本上线后补充到门户页
