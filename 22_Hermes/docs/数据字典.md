# 城市分时电价观察站 数据字典

## 数据库设计说明

### 设计原则
- 遵循第三范式（3NF），减少数据冗余
- 支持按省/市/区三级行政区域查询
- 分时时段同时保留"原始时段名称"和"标准分类"
- 每条数据均可追溯到公开来源
- 独立记录缺失/待验证数据

### 表结构

#### 1. regions（行政区域表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| province | TEXT | 省/自治区/直辖市 |
| city | TEXT | 地级市 |
| district | TEXT | 区/县 |
| province_code | TEXT | 省级行政区划代码 |
| city_code | TEXT | 地级行政区划代码 |
| district_code | TEXT | 县级行政区划代码 |

**设计理由**：支持省-市-区三级行政区域查询，适应不同省份的粒度需求。使用独立的区域表而非在每个时段记录中嵌入省市信息，减少数据冗余。

#### 2. policies（电价政策表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| region_id | INTEGER FK | 关联区域ID |
| policy_name | TEXT | 政策名称 |
| user_type | TEXT | 用户类型（工商业/一般工商业/大工业/居民/农业） |
| voltage_level | TEXT | 电压等级（如1-10kV、35kV等） |
| season_type | TEXT | 季节类型（夏季/冬季/春秋季/不分季节） |
| effective_date | DATE | 生效日期 |
| expiry_date | DATE | 失效日期（NULL表示仍在有效期内） |
| is_active | BOOLEAN | 是否当前生效 |
| description | TEXT | 政策描述 |

**设计理由**：政策和时段分离，一个政策可以包含多个时段。season_type 字段支持不同省份的季节差异（如广东的夏季/非夏季）。

#### 3. time_periods（分时时段表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| policy_id | INTEGER FK | 关联政策ID |
| period_name | TEXT | 原始时段名称（如"高峰"、"尖峰"） |
| standard_category | TEXT | 标准分类（尖/峰/平/谷/深谷） |
| start_time | TEXT | 开始时间（HH:MM格式） |
| end_time | TEXT | 结束时间（HH:MM格式） |
| price | REAL | 电价（元/kWh） |
| unit | TEXT | 单位（默认元/kWh） |
| is_next_day | BOOLEAN | 是否跨日（如23:00-次日07:00） |

**设计理由**：保留原始名称（period_name）和标准分类（standard_category）两个字段，以适应不同省份对时段的命名差异，同时标准化为尖/峰/平/谷/深谷五种分类。is_next_day 字段处理跨日时段。

#### 4. data_sources（数据来源表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| source_name | TEXT | 来源名称 |
| source_url | TEXT | 来源URL |
| publish_authority | TEXT | 发布机构 |
| publish_date | DATE | 发布时间 |
| collect_date | DATE | 采集时间 |
| data_type | TEXT | 数据类型（政策文件/价格公告/新闻报道） |
| reliability | TEXT | 可靠性评估（高/中/低/待验证） |
| remarks | TEXT | 备注 |

**设计理由**：独立记录每个数据来源的完整信息，包括发布机构、时间和可靠性评估，支持数据追溯。

#### 5. data_source_links（数据来源关联表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| source_id | INTEGER FK | 关联来源ID |
| entity_type | TEXT | 关联实体类型（policy / time_period） |
| entity_id | INTEGER | 关联实体ID |

**设计理由**：多对多关系表，支持一个数据来源对应多个时段或政策，也支持一个时段有多个数据来源。

#### 6. missing_records（缺失数据记录表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| province | TEXT | 省份 |
| city | TEXT | 城市 |
| user_type | TEXT | 用户类型 |
| missing_item | TEXT | 缺失内容描述 |
| search_process | TEXT | 检索过程描述 |
| search_date | DATE | 检索日期 |
| status | TEXT | 状态（缺失/待验证/已补充） |
| remarks | TEXT | 备注 |

**设计理由**：严格遵守需求文档要求——"找不到来源的数据必须被明确标注为缺失，而不是被编造"。记录检索过程以便后续复查。

## 数据源切换机制

通过 config.json 配置文件中的 `dataSource` 字段切换：
- `"dataSource": "csv"` — 前端直接读取 CSV 文件
- `"dataSource": "sqlite"` — 前端通过 API 读取 SQLite 数据库

CSV 和 SQLite 两种模式共用同一套前端代码，展示行为保持一致。
