### 详细步骤清单

#### 步骤 1：📖 需求理解（~2 轮）

- 🧠 **大模型推理**：阅读理解 PDF 需求文档，提取关键需求要点（5 省数据、SQLite+CSV 双模式、数据溯源、前端页面功能规格等），规划技术方案选型
- 🤖 **Agent 执行**：调用 `terminal` 安装 `pymupdf` 库，用 Python 脚本通过 fitz 解析 PDF 提取全文文本

#### 步骤 2：🔍 数据搜索（~6 轮）

- 🧠 **大模型推理**：确定电价数据结构（5 省 × 4 时段 × 用户类型）、字段设计（省/市/区/用户类型/时段名称/标准分类/价格/来源）、数据来源策略
- 🤖 **Agent 执行**：
  - 尝试 Google 搜索 → reCAPTCHA 拦截 ❌
  - 尝试 DuckDuckGo 搜索 → 机器人检测页 ❌
  - 尝试 curl 模拟搜索引擎 → 超时 ❌
  - 最终：基于模型训练数据中的已知公开数据，构建 65 条电价记录，所有数据标注"需人工复核"
- **🔄 修正**：用户未修正，但 3 种搜索引擎全部失败，被迫切换方案

#### 步骤 3：🗄️ 数据建模（~2 轮）

- 🧠 **大模型推理**：设计 6 表数据库 Schema（regions、policies、time_periods、data_sources、data_source_links、missing_records），确定表关系与字段类型
- 🤖 **Agent 执行**：

  - 执行脚本创建 SQLite 数据库 `data/sqlite/electricity_pricing.db`

#### 步骤 4：🏗️ 前端构建（~9 轮）

- 🧠 **大模型推理**：设计整体 UI 架构（导航 Tab 系统、省份卡片、24h 电价曲线对比图、详情页表格+图表、数据源中心、缺失数据展示、方法说明页面）

- **🔄 修正**：

## 五、经验教训与总结

### 🟢 做得好的

1. **零依赖前端架构** — 纯手写 HTML+CSS+JS+Canvas，无 CDN、无框架、无外部库，兼容 IIS 和 GitHub Pages，无供应链风险
2. **全面的错误诊断** — 7 次错误全部有明确的根因分析和完整的修复路径，无"盲猜式修复"
3. **数据可追溯性设计** — 6 表 Schema 中独立 `data_sources` + `data_source_links` 表追踪每条数据来源，满足需求文档的溯源要求
4. **双模式架构** — SQLite（后端 API）+ CSV（纯前端）的双模式通过 `config.json` 一键切换，覆盖不同部署场景
5. **完善的验证体系** — 28 项验收标准涵盖文件完整性、数据库结构、API 功能、前端功能、需求对照，确保交付质量

### 🔴 做得不够的

1. **搜索引擎全部被拦截** — 3 种尝试（Google、DuckDuckGo、curl）均失败，被迫使用模型训练数据中的已知信息，未能实现实时数据采集
2. **价格数据依赖估算** — 非从官网实时抓取，部分价格基于政策系数估算，权威性和时效性不足
3. **前端图表交互性有限** — Canvas 手绘图表无法缩放、悬停查看数据、导出，相比 ECharts/Chart.js 体验有差距
4. **Python f-string 陷阱** — 在 f-string 中使用 `$` 符号导致 JS 模板字面量污染，此类语言边界问题可提前规划
5. **缺少自动部署** — 当前仅支持手动部署到 IIS / GitHub Pages，无 CI/CD 流程

### 📈 后续改进建议

1. **引入住宅代理池** — 解决搜索引擎 Bot 检测问题，使实时数据采集成为可能
2. **建立数据更新流程** — 每月定时爬取各省发改委和电网公司最新公告，保持数据时效性
3. **升级图表方案** — 引入 ECharts 或 Chart.js，提供缩放、悬停提示、数据导出等交互功能
4. **扩展至全国 31 省** — 当前仅 5 省，逐步覆盖全部省级行政区
5. **增加时间序列分析** — 展示历史价格趋势、峰谷价差变化、季节性分析
6. **数据交叉验证机制** — 建立多来源自动比对流程，提升数据可信度分级体系
7. **引入 CI/CD** — 配置 GitHub Actions 自动部署到 GitHub Pages，实现推送即上线
